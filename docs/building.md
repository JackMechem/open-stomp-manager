# Building, packaging and releasing

## Getting the source

The app is built on the [open-stomp](https://github.com/JackMechem/open-stomp-lib) library, which it uses as a path
dependency on a **sibling checkout** (`crates/open-stomp-manager/Cargo.toml`). Clone both side by side:

```sh
git clone https://github.com/JackMechem/open-stomp-lib
git clone https://github.com/JackMechem/open-stomp-manager
cd open-stomp-manager
```

```
Projects/
├── open-stomp-lib/        the library: protocol, state, connection engine, protocol docs
└── open-stomp-manager/    this repo: the GUI
```

Changes to the library are picked up by the next `cargo build`; there is nothing to publish in between.

## Building

### With Nix

```sh
nix run                       # build and run
nix build                     # result/bin/open-stomp-manager
nix develop                   # dev shell: cargo, rust-analyzer, ALSA, amidi
```

The flake fetches the library as the `open-stomp-lib` input (`github:JackMechem/open-stomp-lib`, pinned in
`flake.lock`; `nix flake update open-stomp-lib` moves it). To build against your local checkout instead:

```sh
nix run --override-input open-stomp-lib path:../open-stomp-lib
```

### Without Nix

You need Rust ≥ 1.95 (what egui 0.36 requires) and, on Linux, the ALSA headers (`libasound2-dev` on Debian/Ubuntu,
`alsa-lib-devel` on Fedora). macOS and Windows need nothing extra.

```sh
cargo run -p open-stomp-manager
cargo run -p open-stomp-manager -- --replay captures/logs/01-main-session.log --speed 8   # no pedal needed
cargo build --release -p open-stomp-manager
```

### Checks

```sh
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace                 # the app's own tests (activity log)
(cd ../open-stomp-lib && cargo test)   # the protocol and engine tests, driven by capture logs
packaging/check-version.sh             # version consistency
```

## Live preview (styling)

```sh
tools/dev/watch.sh                 # rebuild + relaunch on every change, replaying a capture
STOMP_DEV=log tools/dev/watch.sh   # ... with the activity log open
tools/dev/shot.sh menu menu        # render a state to target/shots/menu.png and quit
```

`watch.sh` watches this crate and the sibling `open-stomp-lib` and restarts the app on each save (needs Nix; it
pulls in `watchexec`). `STOMP_DEV` takes a comma list: `log` opens the activity log, `menu` opens the header menu.
In debug builds **F12** opens egui's style editor and inspector, for trying spacing and visuals live before
moving them into `theme.rs`. `shot.sh` builds on the `STOMP_SCREENSHOT` hook (see
[architecture](architecture.md)).

## Platforms

| | MIDI backend | Release download | Build it yourself |
|---|---|---|---|
| Linux (x86_64) | ALSA | `…-linux-x86_64.tar.gz`: binary, `.desktop` file, icon | `cargo build --release -p open-stomp-manager`, or `nix build` |
| macOS 11+ (Apple Silicon + Intel) | CoreMIDI | `…-macos-universal.zip`: `Open Stomp Manager.app` | `packaging/macos/bundle.sh` (`--native` for this Mac only) |
| Windows 10+ (x86_64) | WinMM | `…-windows-x86_64.zip`: `open-stomp-manager.exe` | `cargo build --release -p open-stomp-manager` |

Platform notes:

* **Linux:** the binary dlopens X11 or Wayland and OpenGL at runtime; the Nix package wraps it with the right
  library path. `packaging/open-stomp-manager.desktop` and `packaging/icons/icon.png` are the desktop entry and icon.
* **macOS:** `packaging/macos/bundle.sh` builds both architectures (`rustup target add aarch64-apple-darwin
  x86_64-apple-darwin`), joins them with `lipo`, fills in `packaging/macos/Info.plist` and ad-hoc signs the bundle in
  `target/macos/`. It is not notarized. CoreMIDI hotplug needs a run loop on the MIDI thread; the library handles
  that.
* **Windows:** release builds use the GUI subsystem (no console window); `--help`/`--version` attach to the
  launching console. `build.rs` embeds the icon and version resource (`packaging/icons/icon.ico`).

Icons are generated by `packaging/icons/make_icons.py`.

## Version

The version lives in one place, `version` under `[workspace.package]` in `Cargo.toml`, and follows
[SemVer](https://semver.org) (0.x: anything may change). `build.rs` adds the short git commit
(`STOMP_GIT_HASH`, empty outside a git checkout); `--version` and the app's version chip show both.

## Continuous integration

`.github/workflows/ci.yml` runs on every push and pull request, on Linux, macOS and Windows: clippy with warnings as
errors, tests, and a release build. A separate job checks the minimum Rust version, and another runs
`packaging/check-version.sh`. Each build job first clones `open-stomp-lib` next to the checkout, at the ref in
`OPEN_STOMP_LIB_REF` (top of the workflow).

## Releasing

1. If the app needs library changes, release the library first (tag it there) and set `OPEN_STOMP_LIB_REF` in both
   workflows to that tag, so the release builds against a fixed library version.
2. Bump `Cargo.toml`, add a `## [x.y.z]` section to [CHANGELOG.md](../CHANGELOG.md), update the version line at the
   top of the README, and run `cargo build` so `Cargo.lock` follows. `packaging/check-version.sh` checks all of this.
3. Commit, then `git tag vx.y.z && git push --tags`. `.github/workflows/release.yml` builds the Linux, macOS and
   Windows packages and publishes a GitHub release with the changelog section as its notes.
